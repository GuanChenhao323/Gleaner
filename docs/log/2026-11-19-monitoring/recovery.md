# 页面会话恢复验证

恢复 alarm 每 60 秒独立协调已授权来源。扩展持久化工作台账号、设备对应的授权来源编号、后端 epoch 和单调序号。心跳只访问本地服务。浏览器内的站点身份经原页确认后才与本次后端进程绑定，设备身份散列的盐保留在浏览器中。工作台令牌与本地来源操作票据分别使用各自的接收端。

授权元数据、任务 ID、来源修订、启停状态和最早可访问时间保存到本地 SQLite。进程退出清空内存凭证。重启保留撤销与暂停状态。已验证过的站点账号在新进程再次使用前需要确认。获准的会话供应完成后，恢复检查遵守站点最小间隔和服务端退避。缺失会话时，原资料及最后成功时间保持可查。

注销或切换工作台账号前，插件撤销该账号记录的本地会话；服务不可达时保留重试状态。用户可在扩展的「本地后端监测」面板打开原作业页核对账号、查询或撤销关联。

## 已执行的检查

- `GLEANER_TEST_CHROME=1 .venv/bin/python -m pytest -q server/tests/test_page_recovery_browser.py` 使用独立 Chromium 配置，加载实际扩展。测试专用扩展清单预授权回环地址与合成作业页。浏览器完成来源关联，关闭作业页后由真实 Chrome alarm 发出心跳。测试服务供应合成凭证后重启，扩展查询得到原任务 ID 与等待凭证状态，再成功撤销。测试主动提前触发同名 alarm 以验证回调，常规周期另行断言为 1 分钟。
- 后端 `test_local_page_host.py`、`test_monitoring_state.py` 和 `test_monitoring_pages.py` 覆盖账号不符时拒绝写入、不同来源修订、拒绝过期票据、无凭证时等待、暂停和撤销跨重启保留、重新验证最早时刻以及后台读取回执。
- 扩展 `resident-monitoring.test.js` 验证 Worker 替换、授权范围内的心跳、跨账号隔离和注销撤销重试。

## 验证边界

浏览器自动化使用合成页面与凭证。已登录个人 Chrome 的 Dashboard 仅用于确认网页会话状态。实机休眠/唤醒、真实学校会话重新授权及 Chrome 登录凭证自动同步尚未通过验收。当前协议执行器只使用已显式供应给本地服务的会话，插件界面提供账号匹配、授权状态和撤销操作。
