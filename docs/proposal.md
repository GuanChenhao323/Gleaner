# Campus Radar｜项目提案与课程技术交付

更新：2026-11-03。当前产品范围已取代 2026-10-21 提案中的产品承诺；旧提案见 [历史归档](archive/proposal-2026-10-21.md)。

## 独立保留的课程技术交付

下表保留既有技术工作及验收责任，不赋予产品功能优先级。具体自研限制见 [开发约定](../CLAUDE.md)，协议规格见 [协议目录](protocols/)。

| 编号 | 技术交付 | 验收依据 | 与产品范围的关系 |
| --- | --- | --- | --- |
| C01 | HTTP/1.1 服务端与客户端、WebSocket、二进制总线 | 协议测试、互通、异常处理、协议文档 | 可供本地产品复用；具体接线方案另经验证 |
| C02 | MQTT Broker、IMAP／SMTP／POP3 | 标准客户端或模拟邮件服务互通、抓包与故障测试 | 独立课程验证；邮箱接入、发信、手机通知不因此进入当前产品 |
| C03 | 反应器、负载均衡、健康检查、采集调度、故障转移 | 并发压测、select／epoll、单节点／多节点、故障恢复对比 | 技术评估环境；不要求本地 MVP 部署分布式集群 |
| C04 | DNS、扫码传输、本地采集代理及长连接 | 对应协议测试、断点续传、重连与校验 | 保留既有开发约定中的技术交付；产品 UI 不必提供这些入口 |
| C05 | 部署、监控、性能报告、真实用户验证与课程演示 | 部署证据、压测图表、抓包、报告、用户验证记录 | 独立核对课程要求，不能给当前产品增加全天候监测或多端同步承诺 |

`server/` 的 socket 层自研约束继续有效；现有实现和测试记录保留。技术模块接入产品需要明确对应产品需求，不能凭模块已经存在就扩大 UI、来源范围或运行承诺。

## 评估与尚待核对的课程要求

- 保留旧技术评估目标作为课程验收对照：单推送节点 5,000 并发连接、入库到在线客户端推送 P99 < 1 秒、2 核缓存命中 API 吞吐 1,000 请求/秒、条件请求流量节省 70% 等。测量条件和已记录结果见 [评估记录](evaluation/README.md)；这些指标不代表来源变化会被秒级发现。
- 继续整理五类对比实验：select／epoll、连接池与 keep-alive、条件请求、MQTT QoS 0／1、单节点／多节点；协议一致性、故障注入与抓包分别提供证据。
