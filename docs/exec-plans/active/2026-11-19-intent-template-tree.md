# 按用户用途组织的网页采集模板树

负责人：待定  
日期：2026-11-19  
状态：设计提案，待实施

## 1. 目标与非目标

### 目标

- 以「记待办」「记日程」「收通知」「存资料」作为模板树的四个根节点，覆盖校园和非校园场景。用户可以对同一网页选择不同用途。
- 为每个根节点提供通用操作：用户选中文字或保留链接，选择用途，核对字段后保存。即使网站没有专用模板，也应能保存内容与来源。
- 允许每个根节点衍生场景、平台和站点模板。例如「记待办 → 课程作业 → Moodle 作业 → MUST Moodle 作业」。Moodle 公告可以挂在「收通知」下，两条分支共用 Moodle 的页面读取能力。
- 采用 JSON 描述模板，用共享 JSON Schema 校验。站点模板通过 `extends` 引用基础规则，用 `overrides` 声明差异，例如某校作业截止时间所在的位置。

## 2. 数据流

### 改动前

```text
网页 + 关键词 → 按站点选择专用规则或通用片段提取 → 预览 → 保存
```

现有普通网页关键词提取可作为「存资料」的起点。Moodle 已有专用作业读取规则，可作为第一个平台样本。JSON 模板继承和四用途采集入口仍待实现。

### 改动后

```text
选中文字、网页链接或页面上的事项
  → 用户选择用途
  → 使用该用途的通用规则，或匹配更具体的平台和站点规则
  → 预览内容、来源及可确认的字段
  → 用户确认保存 → 对应的工作台栏目或资料记录
```

### 自然语言说明

以展览网页为例：选择「记待办」时，“周五前订票”对应动作和截止时间；选择「记日程」时，“周六开展”对应活动和开始时间；选择「存资料」时，只保留展览介绍与原页链接。选择「收通知」时则关注公告正文、发布方和发布时间。模板应同时说明从哪里读、读到的字段代表什么。找不到日期就留空，含义不明确就保留原文供用户确认。

同一份站点覆盖规则可以沿用父模板的标题、描述和事项身份，只替换有差异的字段。对于 Moodle 作业，列表链接和详情页应能指向同一账号、同一站点下的同一项作业，以便后续读取补全原记录。需要滚动加载、打开侧栏等新能力时，由平台适配器实现，JSON 仅引用插件已支持的动作。

**待确认**：四类记录如何映射到现有存储和工作台入口；站点模板首版随插件发布还是支持在线更新。建议先用 MUST Moodle、一个非校园信息页和第二所学校的脱敏样本验证边界，再确定发布机制。

## 3. 文件清单

以下为预计涉及的位置，具体文件布局在实施时确定。

```text
extension/
├── templates/                  [拟新增] 用途模板、平台基础模板、站点覆盖规则与 JSON Schema
├── content/scoped/             [拟复用] 普通网页与 Moodle 等平台的页面读取能力
├── extraction/                 [拟修改] 根据用途与页面匹配模板，输出含来源的字段
├── ui/                         [拟修改] 用途选择、字段核对与保存入口
└── tests/                      [拟补充] 脱敏页面样本、模板继承和通用保存流程测试
```

## 4. 检验清单

- [ ] 在没有专用模板的非校园网页，用户可以只保存选中文字和链接。
- [ ] 同一展览页分别生成订票待办、展览日程和资料记录，报名截止时间与活动开始时间各自进入正确字段。
- [ ] 公告页可保留正文、发布方和发布时间；公告展示期限不会自动变成个人待办的截止时间。
- [ ] 第二所学校只覆盖与 Moodle 基础规则有差异的字段，其他字段仍能从课程列表页和作业详情页的脱敏样本中正确提取。
- [ ] 先保存 Moodle 作业链接，再读取详情，原记录得到补全；另一账号或站点的同名作业仍保持独立。
