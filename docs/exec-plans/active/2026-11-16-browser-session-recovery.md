## 1. 目标与非目标

### 目标

- Chrome 和本地后端恢复运行后，插件自动对齐在线状态、后端运行批次和认证状态；无需打开目标网站标签页。
- 在用户已授权的站点及 Cookie 范围内，按需将浏览器现有凭证同步到本地 `AuthManager`，由实际页面响应验证登录状态。
- 会话失效时引导用户在原网站重新登录；同步新凭证、确认账号后，继续原页面任务，无需重新填写目标和间隔。
- 休眠或后端重启后保留任务 ID、授权绑定、暂停意图和调度限制；合并错过的检查，阻止旧请求覆盖新会话。
- 通过插件与本地后端联调，验证有效会话恢复、过期重新授权、重启、撤销、账号切换和新旧执行路径隔离。

### 非目标

- 保证第三方会话永久有效、修改网站过期规则、自动输入密码/验证码、导出中央认证凭证或实现通用 Refresh Token 机制。
- 电脑关机或 Chrome 关闭时持续监测；操作系统开机自启、唤醒电脑和安装本机常驻服务。
- 自动迁移全部旧事项监测、完成 HTML 到业务事项的正式提取/入库、承诺恢复休眠期间的每一次页面变化。
- 云端 Cookie 托管、新增站点适配、跨账号复用凭证、保存完整认证 HTML、后台定期覆盖有效 Cookie Jar。

### 已核实的现状与实施边界

当前插件已有 `background.js`、`alarms` 权限和启动时重建 alarm 的逻辑，每 5 分钟通过旧 `/api/monitor/due` 领取任务。插件使用浏览器会话获取页面，再向 `/api/monitor/results` 回报提取结果。当前没有 `cookies` 权限，也没有向新版认证模块导入 Cookie 的路径。本包复用已有后台事件入口，增加独立的会话协调流程。

`AuthManager` 已有在线租约、内存 Cookie Jar、导入去重、revision/generation、账号校验和撤销；`PageMonitor` 已有认证检查、按期获取及 HTML 交付。正式服务尚未装配新版组件，页面任务状态只驻内存；旧事项路径的 SQLite 恢复能力不能当作页面路径已经实现。

恢复时需处理三个已识别的边界：`restore()` 当前丢失 `revoked` 状态；重启后没有原账号比对标识，自动导入可能返回 `account_confirmation_required`；认证失败后的重新导入不会改变 `next_due_at`，可能等待正常间隔后才验证。前两项需要明确保护，第三项需要拆清访问预算与展示状态，不能通过清零时间绕过站点限流。

首版保留“无法判断同账号时由用户确认”的策略，不增加跨重启账号指纹密钥。用户确认前保持等待，后台不得自行设置 `confirmed_same_account=true`。因此休眠后的有效会话可自动恢复，后端重启后的恢复可能需要一次确认。

新增能力以显式开关接入本地宿主，控制监听限于回环地址。旧流程默认保留。新页面任务使用独立标识和接口；同一用户、同一规范化目标有旧任务正在执行时，拒绝新执行权登记并提示先停用旧任务。不自动认领已有事项，也不允许两个执行器同时监测同一目标。执行权判断在后端完成，不能仅依赖插件本地标记。

### 实施顺序

| 阶段 | 工作 | 阶段出口 |
|---|---|---|
| 1 | 认证恢复规则、任务持久化、统一宿主与调度入口 | 重启保留任务与撤销/暂停意图，恢复检查可查询且受限流控制 |
| 2 | 本地控制接口、桥接实例绑定、插件 Cookie 同步 | 未打开目标标签页时，授权 Cookie 能进入后端并完成实际验证 |
| 3 | 重新登录交互、状态呈现、新旧执行权隔离 | 失效后可从插件完成重新授权并恢复原任务，旧流程不重复执行 |
| 4 | 合成故障测试与真实浏览器验收 | 第 4 节必验项逐项有证据；未通过项保持未勾选 |

## 2. 数据流

### 改动前

```text
Chrome 后台 alarm（每 5 分钟）
    → 旧 /api/monitor/due → 浏览器凭自身会话取页面
    → offscreen 提取 → 旧 /api/monitor/results → 事项监测状态

手动调试 Cookie 输入 + 模拟 presence
    → AuthManager → PageMonitor → HTMLSink 验证替身

正式插件与 AuthManager：尚未连接
新版页面任务：进程退出后丢失内存状态
```

### 改动后

```text
Chrome 启动 / alarm / 授权操作
    → 后台会话协调 → 本地控制 API → 运行批次、在线租约、授权与任务状态
        ├─ 原后端会话可用 → 到期的受控 GET → 登录证据与账号验证
        ├─ 缺少凭证或会话失效 → 读取已授权站点 Cookie → 导入为 unverified
        │                                          → 到期验证
        └─ 浏览器也未登录 → 提示用户打开原网站登录 → 重新同步与验证

验证通过 → 保留原 ID 的 PageMonitor → HTMLSnapshot → 宿主注入的 HTMLSink
验证失败 → 等待登录 / 等待确认 / 网络退避 / 访问拒绝，分别报告

后端重启 → 从非秘密元数据恢复任务与授权意图
         → 等待真实浏览器在线 → 补充凭证与必要的同账号确认

旧任务执行权：与新页面任务互斥；未切换的任务继续原有路径
```

### 自然语言说明

现有插件直接执行旧事项监测，新版页面模块依赖手动输入凭证。本包增加插件到本地认证管理器的受控通路，由插件提供已授权的浏览器会话及在线信号，由后端统一验证登录状态、维护 Cookie 轮换和恢复调度。后台读取 Cookie 不依赖目标标签页；读取成功只表示浏览器持有凭证，实际登录状态由目标网站的响应确认。

本包的“恢复采集”以原任务继续获取认证页面并完成 HTML 接收回执为准。宿主必须注入 `HTMLSink`；缺少接收端时报告尚未装配，不默默丢弃页面或伪造交付成功。联调可以使用内存接收替身，但证据必须标明替身，不等同于正式事项入库。完整 HTML 和 Cookie 不持久化；关机后重新获取当前页面，不承诺恢复进程退出前尚未确认的 HTML。

### 恢复触发与在线判定

- 保留旧监测 alarm 的职责，新增独立的 60 秒会话协调 alarm，避免将旧页面抓取频率提高到每分钟。启动、安装和每次 Service Worker 加载时确认 alarm 存在；浏览器启动及用户授权操作可直接触发一次协调。
- `alarms` 不唤醒休眠设备；设备恢复后错过的重复 alarm 最多补触发一次。以它和浏览器启动事件触发恢复，不将 `runtime.onStartup` 当作操作系统唤醒通知，不承诺精确到秒的恢复时延。[Chrome alarms](https://developer.chrome.com/docs/extensions/reference/api/alarms)
- 持久化插件实例 `bridge_id`、递增序号、授权范围和后端地址。Service Worker 可被回收，关键状态不只放在全局变量；同一会话的启动、alarm 和授权事件合并执行。[Service Worker 生命周期](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)
- 每次协调先请求能力和状态，再续 180 秒在线租约。心跳只访问本地，不读取全部 Cookie、不访问目标网站。后端不可达或本地 Bearer 失效分别展示“等待本地服务”“请登录 Gleaner”。
- 检测后端 `backend_epoch` 变化或长时间未成功协调后，进入一次恢复检查；恢复前重新核验授权意图。绝对调度期限使用 UTC 持久化，单调时钟只用于当前进程的超时；休眠跨越期限的旧请求应取消或作废，不能仅依赖旧定时器仍然有效。

### Cookie 同步与重新授权

- 在用户明确开启指定站点的后端页面监测时申请 `cookies` 及对应 host 权限，并记录站点、profile、Cookie Store 与任务绑定。`activeTab` 权限不足以承担长期后台 Cookie 读取。
- 使用 `chrome.cookies.get/getAll` 按已登记范围读取，无需目标标签页。桥接方规范化属性并筛选 profile 允许的 Cookie；后端再次校验。隐身和分区 Cookie 沿用当前不支持的边界。[Chrome cookies](https://developer.chrome.com/docs/extensions/reference/api/cookies)
- 后端有效会话先自行验证和接受合法 `Set-Cookie` 轮换，不由周期同步覆盖。首次授权、后端重启、明确认证失败和用户主动重新授权才进入导入流程；同一次恢复对同一份失败凭证最多尝试一次，避免每分钟反复导入。
- Cookie 变化事件去抖后重读，区分正常 overwrite 与删除。事件只提供重新协调的线索，不能据此宣称登录有效；明确退出或权限撤回时停止使用对应会话。后台不在未授权范围扫描 Cookie，也不把后端更新反向写入浏览器。
- 浏览器缺少有效凭证时展示“重新登录网站”；用户点击后打开注册站点页面。网站可以使用自己的 SSO 流程，插件只同步目标站点批准的 Cookie，不取得 CAS ticket、学校密码或中央认证会话。
- 凭证导入携带 `backend_epoch`、`expected_revision`、`request_id` 和原因。网络重试复用同一请求 ID；冲突后重读状态再决定，不盲目覆盖。导入后为 `unverified`，页面验证通过才变为 `valid`。
- 账号不一致时阻止旧任务使用新账号；同账号证据缺失时等待用户确认。撤销是独立、持久的授权意图，重启不得将其变为可自动导入的 `needs_credentials`；重新启用要求明确操作。

### 后端恢复、调度与输出

- 新增 `MonitoringService` 管理页面任务与认证组件的装配、加载、周期驱动和关闭，接入本地宿主。统一运行批次标识，并显式传给其管理的认证实例，避免能力接口与 Cookie 导入使用不同 epoch。
- 在现有 SQLite 存储中新增页面任务及授权元数据表，保留 `task_id`、owner/bridge/store 绑定、profile、精确 URL、revision/generation、启停及撤销意图、最近成功时间和最早允许访问时间；保存路径必须为持久文件，不能使用默认内存库。
- 增加保留 ID 的加载和恢复方法，不通过 `register()` 重建已有任务。认证信息仍只驻内存；重启后有效授权恢复为等待凭证，已撤销授权继续保持撤销，用户暂停的任务继续暂停。
- 恢复验证复用现有获准目标、`Transport` 与 `SessionInspector`。不新增任意 URL 探测口，不用 HTTP 200 或 Cookie 存在判定成功；缺少正面证据与明确登录过期分别返回原因，避免不断要求用户重登。
- 调度分别维护正常任务到期时间与不可提前的访问限制，包括 profile 最小间隔、主机间隔、`Retry-After`。授权完成只排队一次恢复检查，返回 `next_allowed_at`；不得为了“立即恢复”绕过限制。成功验证的页面直接进入正常 HTML 交付。
- 同一认证上下文的恢复串行执行，多任务共享主机访问预算；不得推定同站不同 policy/精确目标可以共用一个 AuthContext。重新授权和撤销沿用 generation 隔离，旧结果不得交付给新会话。
- 对外状态至少区分等待本地服务、等待浏览器、等待凭证、检查中、等待验证时刻、需要网站登录、需要同账号确认、网络退避、已暂停、已撤销和运行中。状态返回任务 ID、原因、最近认证/获取/交付时间与下次允许时间，不返回 Cookie 或 HTML。

### 控制接口与兼容方式

以下为拟新增 `/api/monitor/v2` 控制面，不表示现有端点已经实现。沿用已验证的本地 Bearer 身份，owner 由服务端注入；校验注册插件 Origin、Host、bridge/store 与资源归属。Cookie 接口仅通过专用回环监听开放，不经现有对外网关转发。请求及响应采用 `no-store`，诊断只记录状态和错误码。

| 操作 | 主要输入/输出及约束 |
|---|---|
| `GET /capabilities`、`GET /status` | 返回运行 epoch、允许的 profile/范围和当前用户状态；不返回凭证 |
| `PUT /bridges/{bridge_id}/presence` | 单调递增序号、启用状态；返回租约状态，重复序号不延长租约 |
| `POST /auth-contexts`、`GET /auth-contexts/{auth_id}` | 以批准的 profile/目标范围和 bridge/store 建立或读取上下文；创建支持幂等 |
| `PUT /auth-contexts/{auth_id}/cookies` | 属性完整的最小 Cookie 快照及版本字段；返回待验证元数据，大小限制沿用组件 |
| `DELETE /auth-contexts/{auth_id}/cookies` | 撤销本地授权、清空凭证、隔离旧执行；不注销浏览器中的网站会话 |
| `POST /auth-contexts/{auth_id}/checks` | 合并、排队受限恢复检查；不同步执行任意远端请求 |
| `POST /page-tasks`、`GET /page-tasks`、`GET/PATCH /page-tasks/{task_id}` | 创建、查询、暂停及显式恢复原任务；校验版本、范围和新旧执行权互斥 |

旧 `monitoring-v1.openapi.yaml` 是事项监测提案，不用于生成这组页面客户端。实施时新建 v2 Schema，并同步 IC-003 中相关待实现项的实际状态；本次计划编写不改动这些文档。首版由插件承载授权、状态与恢复入口，工作台的全面界面改造留在后续集成。

## 4. 检验清单

### 插件与控制通路

- [ ] 首次使用仅在用户操作后申请相应权限；拒绝权限时不读取、不导入 Cookie，旧功能仍可运行。
- [ ] 浏览器仅打开空白页、目标网站所有标签页关闭时，插件仍能读取批准的测试 Cookie 并同步到本地后端。
- [ ] alarm 缺失可重建；Service Worker 回收后实例、序号与授权意图保持，事件并发不会重复导入或重复检查。
- [ ] 本地协调每 60 秒不触发远端页面保活，不周期性发送 Cookie；旧 5 分钟任务频率不受影响。
- [ ] 后端未启动、Gleaner Bearer 过期与第三方会话过期显示不同状态；恢复本地连接后继续协调。
- [ ] 非回环入口、未注册 Origin、越权 owner/bridge/store、非法范围和过大 Cookie 导入均被拒绝。
- [ ] 相同请求重试幂等；旧 epoch、过期 revision 和同 ID 不同内容可区分，冲突不盲目覆盖。

### 会话与任务恢复
