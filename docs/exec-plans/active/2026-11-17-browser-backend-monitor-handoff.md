# 采集分支整合与监测执行切换计划

状态：交互方案已讨论；浏览器与后端监测的自动切换尚未实现。

## 已确认的整合决定

1. Chrome 插件的采集界面和交互采用 `feature/campus-radar-web-capture-monitoring-20261117`，不要求保留旧版插件界面。
2. 新账号只展示信息源入口，由用户自行添加；注册时不自动订阅公共来源。
3. 纳入 `dengshen/item-service` 的事项分类规则和测试。
4. 启用监测后，页面保持打开时由浏览器插件按计划刷新和读取；用户关闭页面后，插件向后端报告该来源的页面状态，由后端 `PageMonitor` 通过 URL 和已授权会话执行后续检查。

用户自行处理现有文档；本次整合仅新增本计划文件。

## 目标交互

- 保存监测条件时关联用户、来源、URL、原提取条件、账号和监测周期。
- 页面打开且页面和账号匹配时，后端将到期检查交给插件；插件刷新对应标签并回传结果，保留已有的编辑保护。
- 页面关闭或跳转后，插件按来源报告页面不可用；后端在后续到期检查时切换到该来源的协议监测。页面重新打开并确认匹配后，后续检查切回插件。
- 每个来源的状态独立；同一监测周期只能有一个执行方。执行权切换时需要处理进行中的任务、超时、重试和过期回执。
- 插件与后端通信异常时，页面状态标为未知并重新核验，不能永久依赖一次关闭事件。Chrome 整体退出后是否允许协议监测继续，尚待用户决定；当前 `PageMonitor` 要求浏览器桥接在线。

## 接入工作

- 补齐插件到后端的来源状态报告、会话授权和 Cookie 桥接；凭证按站点和账号限制，仅在必要时传递，不写入日志。
- 将插件保存的来源、条件和任务身份映射到 `PageMonitor`；接入现有后端服务生命周期、统一调度和结果交付。
- 将协议获取的 HTML 按原条件提取成与浏览器结果可比较的数据，再复用事项的版本、状态和通知流程。无法提取相同内容时，保留旧结果并明确显示失败或暂不支持，不得视为无变化。
- 尊重已有站点配置和 URL 范围；扩展支持范围需要单独实现和验证，不能假设所有网页可由 HTTP 原始 HTML 重现。
- 整合后验证页面开关及重新打开、一次检查恰有一个执行方、Cookie 失效、浏览器/后端中断、动态内容差异和历史资料不被误覆盖。

## 本次合并边界
