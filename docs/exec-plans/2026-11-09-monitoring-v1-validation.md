## 1. 目标与非目标

### 目标

- 先支持一种已登记的 Moodle 作业详情页，对显式保存的目标执行只读获取、认证识别和稳定定位。
- 完成来源管理、内存会话、调度、受控网络获取和观察结果交接，支持失败分类、暂停、恢复与重复交接。
- 用调试工具替代尚未完成的 Chrome 桥接及 Extractor / Item Service，通过独立测试证明监测模块的行为。
- 用 Computer Use 检查真实浏览器环境和操作流程；在授权 Moodle 上完成至少 130 分钟的持续运行，保留脱敏证据。
- 第 4 节所有必验项均有通过证据并打勾，才将本轮开发标为完成。

### 非目标

- 正式 Chrome Cookie/心跳桥接、正式 Extractor / Item Service、工作台功能及整个产品的端到端验收。
- 新增事项发现、公告/活动/任意校园网页适配、全天候监测、无限会话续期、自动登录或代输密码。
- 旧监测执行权的生产切换、生产数据迁移、公开发布及云部署；本轮使用独立调试数据库，生产开关保持关闭。

### 已确定的开发方式

- 用户已明确允许本模块使用现成 HTTP 库。选择 `HTTPX AsyncClient + asyncio`，保留 `RemoteTransport` 边界；例外记录在本计划与 Ruff 局部导入说明中，其他模块的自研协议约束继续有效。按用户缩小后的文档范围，不修改 CLAUDE.md 或 IC-003；其中网络实现的差异由本轮明确授权覆盖，协议语义仍遵守 IC-003。
- 使用现有 BeautifulSoup/lxml、pytest/pytest-asyncio、Ruff、fake_moodle 和 CI。先沿用 Python 3.12 基线，记录实际依赖版本；无需新增分布式队列或独立生产服务。
- 首批为 `/mod/assign/view.php` 作业详情页，实际测试目标从授权会话内已允许的页面选取；课程页仅用于定位入口。未验证的页面保持 unsupported。
- 真实探测补充：MUST 的 robots 在携带会话后首跳 303 到 `/my/`，严格规则无法取得可用策略。本轮按已有精确目标授权增加显式 `registered-target` 回退，仅允许唯一登记的完整作业 URL；默认仍为 strict。回退模式和触发原因单独记录，已声明的禁止规则、认证错误、未知 HTML、网络错误和其他跳转仍阻断。
- 本轮用户已授权通过 Computer Use / 现有 Cookie-Editor 使用其受控的 Moodle 会话进行真实验证，无需重复申请同一授权。沿用已登记的只读路径和速率，不扩大账号或来源范围；合作授权材料/有效期的缺口如实保留，不编造学校授权信息。现有会话失效且需要本人登录或验证码时，仅暂停真实访问，继续可独立完成的本地工作。
- 无人监管阶段，Codex 自行决定命名、文件拆分、测试组织及常规修复。资料检索、脱敏样例整理和独立审查交给 Luna-max；需要其结论的工作等待结果后继续，由 Codex 复核。
- Luna 可抽样检查提取遗漏和提出反例；周期提取及自动通过判定使用确定性程序和预先定义的期望值。Cookie、完整认证页面和未脱敏个人数据不交给子代理。
- 仅遇到扩大来源/权限/交付范围、改变接口语义、不可逆操作或必须本人完成的重新登录/验证码时请求用户介入；其他可独立推进的工作继续执行。未完成的真实验收保持未勾选。

### 四阶段实施

| 阶段 | 工作包 | 阶段出口 |
|---|---|---|
| 1 · 单页突破 | 统一约束；建立只读调试入口；验证一类作业页的 HTTP 获取、登录判定与目标定位 | 指定目标能由后端取得；登录页、目标缺失和结构不符可区分；最小解析样例测试通过 |
| 2 · 模块闭环 | 接入 Source/Target、Session、Scheduler、Transport、Handoff；增加桥接和业务替身 | 独立调试环境可周期运行、查询状态、保存并重放观察；替身信息与真实证据明确区分 |
| 3 · 故障验证 | 用本地站点、可控时钟、临时数据库验证错误、并发、限流、重启和幂等 | 失败不会伪装为成功；请求与状态符合契约；全部必需自动测试通过 |
| 4 · 真实持续运行 | Computer Use 检查环境、关闭 Moodle 标签页，运行授权只读脚本并复查证据 | 首轮成功后持续至少 130 分钟，跨过 120 分钟后仍有真实获取与解析成功记录；全部必验项通过 |

阶段 1 的真实探测仅在对应传输保护和本地测试通过后执行。阶段 2 完成后即执行一次短时真实冒烟，尽早暴露会话/解析问题；正式长时验收仍在阶段 3 通过之后。

## 2. 数据流

### 改动前

```text
Chrome 采集 → 既有 Capture / 事项存储
旧 monitor/due、monitor/results → 既有监测状态与业务流水线

IC-003 后端执行器、Chrome 会话桥接、ObservationSink：尚未接通
真实 Chrome 已有 Moodle 登录态和 Cookie-Editor：仅确认环境，不构成后台成功证据
```

### 改动后

```text
授权 Chrome 会话 → 本机调试凭证输入 → 内存 AuthContext
调试桥接替身 → 在线租约 / 模拟心跳
独立调试库中的已保存目标 → Source / Target 登记
                                      ↓
Scheduler → 受控 HTTPX Transport → Moodle 作业页 / 本地 fake_moodle
                                      ↓
认证判定 → SiteAdapter 定位目标 → ObservationBatch → 本地 outbox
                                      ↓
调试 Sink / 确定性内容比较 → 模拟 ApplyReceipt → 独立调试状态
                                      ↓
脱敏报告：真实请求证据 / 目标解析结果 / 模拟业务回执分别记录
```

### 自然语言说明

现有业务流水线和插件仍在开发，本轮从独立保存的调试目标开始，将监测模块真正执行的网络、认证、解析、调度与交接行为串起来。输入替身只提供受控凭证和在线信号；输出替身只校验观察批次、比较选中目标的规范化标题/正文并返回模拟回执，不解释事项类型、截止日期或用户字段。正式内部结构保持 IC-003 约定，替身的 `execution_mode=debug`、`sink_kind=stub` 等标记放在运行报告外层，不擅自扩展既有回执 Schema。

模拟回执可以在独立测试数据库中驱动完整状态机，包括成功与失败分支；不得写入正式事项、业务版本或正式 `last_success_at`。真实试用报告分别记录请求成功、认证通过、目标解析成功和模拟交接结果，不能将 `check.succeeded` 的模拟结果当作正式业务应用证据。

期望值由人工核对和固定脱敏样例提前定义，测试调用真实待测代码。覆盖正文实质变化、标题变化、无关页面区域变化、目标缺失与结构改变；只对约定的目标内容做确定性比较，保留有意义的文本差异。真实网页内容仅在受控进程内处理，提交的记录限于时间、匿名目标编号、状态、长度、摘要和错误码。

Computer Use 用于浏览器和调试工具操作；Chrome DevTools 查看浏览器自身请求，后端脱敏日志验证 Python 到 Moodle 的流量。后端断网由本地传输测试或明确的进程级故障注入复现。持续运行期间不刷新 Moodle、不用浏览器探测保活；模拟心跳每分钟仅访问本地，不请求学校站点。
