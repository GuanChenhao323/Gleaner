# 浏览器插件｜当前目标与迁移要求

更新：2026-11-03。产品需求与验收统一引用 [产品定义](product-definition.md) F01–F09、US01–US09；实现进度见 [里程碑](milestones.md)。本文件不宣称以下目标均已实现。

## 当前目标流程

1. 用户在 Chrome 中打开指定 Moodle 或校园页面；插件识别同页候选信息，由用户单选或多选。
2. 插件将选中内容、来源及事项定位信息发送至本地后端；插件与程序优先完成字段提取与分类，效果不足时才评估 LLM。
3. 后端按事项身份去重、持久化，返回明确的保存结果；后端不可用、部分保存失败或解析失败时不得虚报全部成功。
4. Flutter 工作台按三种信息类型管理记录；只对已保存、支持且启用监测的事项检查来源。
5. Chrome 与本地后端运行时可周期检查，不要求原标签页保持打开；该能力需逐来源验证，失败须明确反馈。

## 既有实现与迁移差距

| 既有实现（历史记录，待复核） | 当前基线要求 | 迁移时需要解决 |
| --- | --- | --- |
| 保存整页或选中文字为 `clip` | 同页识别多个候选事项并选择保存 | 页面适配、多选结果与逐项保存反馈 |
| `POST /api/clips {url, title, text}`，单个 `item_id` 返回值 | 同一 URL 可有多个独立事项 | 稳定事项标识、批量语义和重复采集；旧请求格式不能视为已满足新契约 |
| `clip`／`page` 与其他事项不按链接合并 | 三类产品信息、同一事项重复采集不直接新增 | 内部类型映射与身份迁移；保留用户内容及来源版本 |
| `POST /api/sources` 添加整页／RSS 订阅 | 只监测已保存事项的相关内容 | 不自动保存用户未选的新信息；采集与监测能力分别标记 |
| 插件登录旧服务端账号，可配置服务器地址 | 插件连接本地后端，云账户不在当前 P0 | 本地连接鉴权与权限设计待验证；不据此删除现有安全措施 |
| Chrome／Edge 共用 Manifest V3 实现 | 当前验收基线为 Chrome | Edge 历史兼容声明不代表首版验收承诺 |

具体接口变更应在 R1/R2 实施时更新 [API 文档](protocols/rest-api-and-sync.md) 并记录兼容方式。本次仅统一文档，没有修改接口或插件代码。

## 权限、监测与验证

- 用户点击采集时读取指定页面，权限遵循最少化原则，不获取无关表单、密码或 Cookie。
- 现有 `activeTab` + `scripting` 的单次读取权限不能直接证明后台可重新获取；关闭标签页后的授权、会话、后台调度和恢复行为属于 Spike 02 的验证内容。
- 认证失效、获取失败、暂不支持监测分别显示；失败不更新最后成功检查时间，不显示为无变化。
- 来源访问范围、速率及测试数据规则遵循 `CLAUDE.md` 和 `docs/integrations/`；第三方 LLM 如被选用，再明确发送内容与隐私策略。
- 旧插件测试和安装说明见 [历史插件记录](archive/browser-extension-2026-10-26.md)，仅证明当时的剪藏／订阅流程；当前验收需覆盖多选、同 URL 多事项、三类分类、来源版本、用户修改及错误路径。
- Chrome 本地加载入口：`chrome://extensions` → 开发者模式 → 加载已解压的扩展程序 → `extension/`。上架安排待定，不阻塞本地验证。
