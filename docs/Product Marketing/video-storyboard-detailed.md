# Gleaner｜产品营销视频细化分镜与素材约束

> **版本**：v0.3 · 2026-11-19  
> **状态**：预制作方案（Pre-production），用于镜头设计和素材规划；尚未批准为最终拍摄脚本  
> **上级文档**：[产品营销视频叙事大纲](./video-narrative-outline.md)  
> **目标**：将 7 个叙事板块细化为可执行的镜头、画面信息、动效与转场，并明确可虚构素材的边界。  
> **建议规格**：16:9 横版；约 88 秒；7 个板块、25 个实际镜头。时间为节奏参考，可根据音乐与实拍素材调整。

## 0. 创作定位与统一视觉规则

### 0.1 一句话故事

**重要信息分散在不同的数字窗口里；Gleaner 让用户将值得关注的信息采集、整理，并在已保存来源发生变化时持续跟进。**

故事的开端具有普遍性，完整操作演示采用大学生的课程作业作为具体案例（**especially for students**）。

**连续的视觉动词**：Scattered → Focused → Captured → Organized → Updated → Unified。

### 0.2 Window-first：以应用窗口为画面主体

- **窗口是主角**：网页窗口、浏览器插件面板、工作台、Inbox 和事项详情窗口可以脱离操作系统桌面独立存在。
- **不要求展示整台 Mac**：Mac 风格设备只是一种可选开场参考；菜单栏、Dock、桌面壁纸不是固定构图要素。
- **点击即聚焦**：用户点开插件后，镜头立刻推进到插件面板；放大面板可以占据画面主要面积，确保文字可读。
- **窗口外是可设计空间**：使用深色纯背景、渐变、抽象空间、悬浮信息层或 2.5D 透视。外部背景服务于窗口主体。
- **一个镜头只传达一个主要信息**：少量可读字段配合有目的的动效，避免同时显示过多文字或效果。
- **避免镜头漂移**：尽量一镜一个主要摄影机动作（推进、横移、拉远或固定），同时明确起始帧和结束帧。

### 0.3 统一的视觉 DNA（待根据正式 Logo 微调）

| 视觉维度 | 暂定规则 | 作用 |
| --- | --- | --- |
| 空间 | 深色中性背景、悬浮应用窗口、清晰的前后层次 | 托起产品界面，形成高级感 |
| 配色 | 中性色为底；从正式 Gleaner Logo／界面抽取一种主强调色；变化提示另用有限状态色 | 保持品牌一致、避免彩色信息噪声 |
| 形状 | 统一圆角、阴影、窗口厚度；信息卡片采用同一套圆角几何 | 让跨镜头元素像同一个产品世界 |
| 运动 | 开头克制地提出“信息分散”；Problem 通过不同网页依次切换，加上最终的大字反问；品牌登场短促、精准；变化时强调，结尾收束 | 用节奏呈现“跨应用切换 → 聚焦 → 有序” |
| 镜头 | 以正视和轻微 2.5D 透视为主，操作细节始终保持可读 | 避免 3D 旋转牺牲 UI 识别 |
| 声音 | 开头叠加消息提示／窗口切换声，采集处出现确认感，变化对比处高潮，Logo 落点收尾 | 声音强化信息因果与节奏 |

> **使用原则**：先锁定每个镜头的起始／结束画面，再决定运动和音效。参考 `content-engine` 的 visual DNA、start-frame-first 与节奏设计思路；具体生成模型和剪辑工具尚不决定。

## 1. 素材约束模型：允许 fake 什么

### 1.1 三类素材

| 类型 | 名称 | 允许的操作 | 边界与验证 |
| --- | --- | --- | --- |
| **A** | 真实产品素材（Real Product） | 录制当前可运行的浏览器插件、Gleaner 工作台、Inbox、状态管理和变更详情；可裁切、放大、调色、加遮罩 | 关键按钮、交互因果和结果必须与实际产品功能一致 |
| **B** | 合成／重设计的演示素材（Synthetic Demo） | 虚构课程名、作业正文、日期、校园网页、邮件和聊天内容；美化页面排版；用模拟网页注入可重复的内容变化 | 只能合成**数据、场景与视觉样式**，不可暗示已接入所有 App／真实校园平台或拥有尚未完成的功能 |
| **C** | 纯 Motion Design（Visual FX） | 悬浮窗口、卡片飞行、信息拆解、字段重组、光线、粒子、时间变化强调、Logo 聚合 | 动效是帮助理解的视觉隐喻，不代表产品实际有“飞行卡片／实时推送／全自动跨 App 抓取”等功能 |

**必要时允许 A+B+C 合成同一镜头**：例如用真实插件录屏作 UI 核心，替换为合成作业内容，再制作关键词命中或卡片飞行特效。每个镜头均标记主要素材类别。

### 1.2 不得越过的真实性边界

1. **功能不可凭空增加**：开头展示多个 App 仅代表信息分散，不表示 Gleaner 已接入或实时读取它们。
2. **保留用户主动操作**：Capture 的关键词搜索、预览、选取和保存属于用户操作。演示卡片可以虚构，步骤因果不能跳过。
3. **监测必须有条件**：仅对已保存、可监测且启用监测的来源进行检查；经过下一次**成功检查**后才出现变化提示。不得将其剪成“原网页刚改、任意地点立即推送”的产品承诺。
4. **差异必须可追溯**：同一作业的标题、来源、旧截止时间与新截止时间保持一致；Before / After 应清楚展示改变了什么。
5. **不得冒充生产环境**：模拟网页、虚构账号及合成数据统一作为演示素材。成片可在片尾或说明中标注 `Demonstration with simulated data`，不把模拟内容包装为真实校园用户证据。
6. **Logo 不可随意改形**：最后一横一竖与“标签形”的几何关系需以最终确认的 Logo 文件为准；动画可以夸张，落版必须准确。

### 1.3 单一贯穿用例（固定道具）

为避免镜头间信息失配，先冻结一组**完全虚构的演示数据**：

| 字段 | 演示值 |
| --- | --- |
| 来源类别 | Moodle 风格的模拟课程作业页 |
| 课程 | Computer Networks |
| 作业标题 | Socket Lab 03 — TCP Echo Server |
| 简述 | Implement and submit a TCP echo server |
| 初始截止 | **Fri, Dec 11, 2026 · 23:59** |
| 修改后截止 | **Thu, Dec 10, 2026 · 23:59** |
| Gleaner 类型 | 待办（Todo） |
| 保存状态 | 未完成（To do） |
| 变化事件 | 截止日期提前一天；同一个来源、同一条作业 |
| 来源地址 | 使用虚构测试域名（如 `moodle.example.test`），不展示真实学生隐私、Cookie 或有效凭证 |

除非后续替换整个测试素材包，**所有镜头复用这一组名称、字段和日期**。视觉元素可重排，数据不能前后矛盾。

## Scene 01

**Introducing · 信息无处不在（00:00–00:04，2 镜头）**  
**板块目标**：用一个简短的命题引入“重要信息散落在不同网站／应用”。不展示品牌，不提前制造多窗口拥挤。

### Shot 01A｜提出命题（00:00–00:01.8）

- **主窗口 / 画面内容**：暗色中性空间中央出现简洁文案 `Information is everywhere.`；可搭配少量网页、邮件、应用的抽象符号。
- **起始帧**：深色背景，留白充分；摄影机基本固定。
- **过程**：文字从低透明度、轻模糊中显现；少量来源符号逐一浮现，以“种类不同”为核心，不要求同时展出很多 App。
- **结束帧 / 转场**：信息符号退至次要层级，中央留下可供生成网页窗口的空间。
- **素材**：B（抽象来源／合成内容）+ C（文字与层次动效）；**叙事信息**：重要信息无处不在。

### Shot 01B｜从概念进入具体网页（00:01.8–00:04）

- **主窗口 / 画面内容**：简短出现不同来源的视觉线索，随后形成**单一** Moodle 风格课程网页窗口。
- **起始帧**：命题文案和少量符号尚在画面中。
- **过程**：来源线索逐渐淡出；一个网页窗口由简化轮廓展开为清晰页面，镜头向其推进。
- **结束帧 / 转场**：课程网页填满主要画面，直接接到 Shot 02A；**不以多窗口堆叠作为开头的视觉钩子**。
- **素材**：B（模拟网页）+ C（页面展开）；**音效**：从抽象氛围落到第一次网页打开的轻微提示。

## Scene 02

**Problem · 信息来源增多与持续管理成本（00:04–00:18，5 镜头）**  
**板块目标**：依次出现典型应用窗口，让观众理解来源多、需要反复查找和整理。最后直接用大字字幕提出变化风险，无需设计公告更新或手工记录对比画面。

**旁白**

> Course pages. Announcements. Emails. The list keeps growing. Finding what matters takes time. Organizing it takes effort. And when something changes—will you even notice?

### Shot 02A｜Course pages：课程网页（00:04–00:06）

- **主画面**：单独展示模拟 Moodle 作业页，短暂聚焦 **Socket Lab 03 — TCP Echo Server**。
- **起始／动作／结束**：承接 Scene 01 的课程网页 → 轻微推进任务标题 → 快切公告网页。
- **旁白**：Course pages.
- **素材**：B+C。页面内容可合成。

### Shot 02B｜Announcements：公告网页（00:06–00:08）

- **主画面**：一个学院／校园公告列表的合成网页，公告标题清楚可读。
- **起始／动作／结束**：公告替代前一窗口 → 突出一条重要信息 → 快切 Email。
- **旁白**：Announcements.
- **素材**：B+C。不要表现“Gleaner 已自动接入此公告”的效果。

### Shot 02C｜Emails：邮件窗口（00:08–00:10）

- **主画面**：合成的邮件应用窗口，简短展示一封与学习安排相关的邮件。
- **起始／动作／结束**：邮件窗口独立占据主体 → 聚焦一条内容 → 快切下一个来源。
- **旁白**：Emails.
- **素材**：B+C。

### Shot 02D｜更多来源、寻找与整理（00:10–00:15）

- **主画面**：依次快速切过日历、在线文档、课程资源等窗口；随后在一个网页中搜索信息，再切换至日历／待办窗口录入内容。
- **起始／动作／结束**：邮件离开 → 更多来源依次取代彼此 → 搜索、选取、手动记录的连续操作 → 最后一个窗口淡出。
- **旁白**：The list keeps growing. Finding what matters takes time. Organizing it takes effort.
- **素材**：B+C。**每个时刻只有一个主要应用窗口**，不做多 App 的平铺或爆炸。

### Shot 02E｜大字字幕提出反问（00:15–00:18）

- **主画面**：干净深色背景，中央以**大号、高对比字幕**写出：**And when something changes—will you even notice?**
- **起始帧**：此前应用窗口已淡出；画面留白充足。
- **过程**：文字简洁淡入，必要时自然分为两行，保证能在旁白结束前读完。背景保持安静。
- **结束帧／转场**：旁白后留极短停顿；文字淡出，接着同位置显示 **Introducing Gleaner**。
- **旁白**：And when something changes—will you even notice?
- **素材**：C（纯字幕与基础淡入淡出）。
- **限制**：不专门设计原公告 Updated 状态、旧记录对比、炫目特效或复杂镜头运动；清楚的文字足够传达悬念。

## Scene 03

**Meet Gleaner · 品牌登场与插件变形转场（00:18–00:24，4 镜头）**  
**板块目标**：用一次快速且精确的品牌转场完成 **Introducing Gleaner → Gleaner → G → 插件图标 → 插件面板**，并让品牌旁白自然承接 Capture。

### Shot 03A｜Introducing Gleaner 居中出现（00:18–00:20.2）

- **主窗口 / 画面内容**：Problem 结束时的大字反问字幕已淡出，背景保持简洁，中央出现大型标题 **`Introducing Gleaner`**。
- **起始帧**：大字反问字幕刚淡出，画面保留干净的深色背景。
- **过程**：标题淡入并略微放大，声音从先前的频繁切换转为干净的音乐主旋律；**介绍产品背景和用途的旁白从此处开始**。
- **结束帧 / 转场**：`Introducing` 将开始淡出，`Gleaner` 被保留在中央。
- **素材**：B（背景）+ C（排版动效）；**信息重点**：品牌正式登场。

### Shot 03B｜只留下 Gleaner（00:20.2–00:21.3）

- **主窗口 / 画面内容**：深色简洁背景，中央仅有放大的 **`Gleaner`** 字样。
- **起始帧**：上一镜头的标题保持字距、基线一致。
- **过程**：`Introducing` 完全淡出，`Gleaner` 短暂停留供观众辨认；避免多余相机运动。
- **结束帧 / 转场**：除首字母 `G` 外，其余字符开始逐渐淡出。
- **素材**：C；**信息重点**：强化品牌名称的识别。

### Shot 03C｜G 从文字形态变为图标（00:21.3–00:22.1）

- **主窗口 / 画面内容**：`leaner` 淡出，只保留居中的 **`G`**。
- **起始帧**：完整 Gleaner 字样。
- **过程**：`G` 迅速从字形向正式插件 Logo 的可识别轮廓变形；保留视觉中心位置，避免晃动。
- **结束帧 / 转场**：一个完整、可用来映射插件入口的图标。
- **素材**：C；**几何约束**：需确认真实 Logo／插件图标的路径，不得按普通字体 `G` 随意替代。

### Shot 03D｜图标落入浏览器并打开插件（00:22.1–00:24）

- **主窗口 / 画面内容**：浏览器右上方的扩展区域出现；中央 `G` 图标迅速缩小，落到 Gleaner 扩展的位置。
- **起始帧**：图标位于画面中央；浏览器轮廓或工具栏开始显现。
- **过程**：一次连续的快速缩放与位移，图标与扩展位精确对齐；光标点击，插件面板立即展开；摄影机**快速推进插件面板**，去掉多余的浏览器壳体。
- **结束帧 / 转场**：插件已打开，输入框和主要操作内容位于画面中心；Scene 04 **直接接着插件操作**，不再切回完整课程网页重建背景。
- **素材**：A（真实插件打开动作）+ C（图标路径与镜头推进）；**信息重点**：品牌符号无缝落地为真实产品入口。

## Scene 04

**Capture · 网页信息采集（00:24–00:42，4 镜头）**  
**板块目标**：清晰证明 Gleaner 的输入、提取、预览、选择、保存流程。此段可以更快切镜，操作对象始终可读。

### Shot 04A｜插件面板接住来源上下文（00:24–00:28）

- **主窗口 / 画面内容**：已打开的 Gleaner 插件面板占据主体画面。面板顶部显示当前来源是模拟 Moodle 作业页，背景浏览器仅保留少量作为上下文。
- **起始帧**：无缝承接 Shot 03D；插件已经打开、输入区域清晰可读。
- **过程**：通过面板中的页面标题或来源信息，让观众理解此刻操作的是 `Socket Lab 03 — TCP Echo Server`；**不再切回完整原网页**。
- **结束帧 / 转场**：焦点落入关键词输入框，直接启动 Shot 04B 的键入动作。
- **素材**：A（真实插件面板）+ B（模拟来源）+ C（轻微聚焦）；**防误解**：不得借由重设计暗示已支持任何网站或任何 App 的无条件采集。

### Shot 04B｜输入关键词（00:28–00:32）

- **主窗口 / 画面内容**：Gleaner 插件**特写**，可见 `你想提取什么？` 的输入框和提取按钮。
- **起始帧**：面板占据画面主要面积，光标在输入框。
- **过程**：键入 `Socket Lab`，触发“提取”；用细微的输入音效和明确的按钮反馈强调动作。
- **结束帧 / 转场**：面板下方留出展示结果的位置，镜头不再频繁移动。
- **素材**：A（产品输入行为）+ B（合成数据）+ C（镜头放大）；**核心信息**：用户主动指定关心的内容。

### Shot 04C｜匹配、预览、选择（00:32–00:37）

- **主窗口 / 画面内容**：插件的结果列表展示 `Socket Lab 03`，可看到标题、相关内容、来源和已识别的截止信息。
- **起始帧**：结果区为空或加载中。
- **过程**：匹配卡片按层级依次展开，焦点停在目标作业；使用产品实际支持的预览／选择动作。
- **结束帧 / 转场**：目标卡片被确认选中，保存按钮成为唯一高对比操作点。
- **素材**：A+B+C；**不得制造**当前尚未支持的“无限网页自动全量抓取”或多 App 读取能力。

## 3. 镜头间连续性与验收检查

### 3.1 关键连续转场

| 衔接 | 具体转场关系 | 设计目的 |
| --- | --- | --- |
| 01 → 02 | 信息分散命题逐渐转化为第一扇课程网页 | 将抽象概念落到具体场景 |
| 02 → 03 | 大字反问淡出 → 同一位置出现 `Introducing Gleaner` | 直接从问题切到品牌回答 |
| 03 → 04 | Introducing Gleaner → Gleaner → G → 插件图标 → 点击展开并立即进入输入框 | 品牌与产品使用连贯，避免退回网页 |
| 04 → 05 | 保存回执后的作业卡片飞入工作台、拆分并重组 | 强化 Capture → Organize 的连续因果 |
| 05 → 06 | 从工作台里的同一个截止日期匹配切回原始网页 | 让“来源变化”有明确参照 |
| 06 → 07 | Before / After 差异卡片化为线条，吸引其他信息元素聚集 | 差异化高潮自然导向品牌收束 |

### 3.2 每镜头的质量门槛

- **可读性**：关键信息（标题、关键词、截止时间、变化前后对比）停留足够久，观众无需暂停即可理解。
- **单一意图**：每个镜头能用一句话说清自己要证明的东西；无意义视觉炫技删掉。
- **视觉一致性**：同一信息卡片的标题、日期、色彩角色、圆角和信息层级保持一致。
- **动作闭环**：镜头必须描述开始、动作、结束，避免“卡片一直漂浮”却没有明确落点。
- **功能可信**：A 类真实操作需要复录、核对保存结果与监测结果；B 类仅改内容或造演示情境；C 类不伪装成原生功能。
- **品牌一致性**：最后 G → 标签的绘制路径必须先经过 Logo 几何确认。
- **声音节奏**：窗口失序与信息出现相对应，采集成功有确认落点，差异对比是全片最强声音与画面强调点。

### 3.3 最小素材清单（后续制作阶段使用）

| 素材组 | 最小需要 |
| --- | --- |
| A · 产品录屏 | 关键词提取→预览→保存成功；工作台分类／详情；Inbox 变化状态；来源差异对比 |
| B · 演示数据 | 一套模拟 Moodle 作业页的修改前／修改后版本；多来源问题段的 Email／Calendar／公告／笔记窗口；一致的文案与日期 |
| C · 动效资源 | 一套悬浮窗口模板；卡片分解／归类动画；变化高亮和 Before/After；Logo 矢量路径与逐笔动画 |
| 声音 | 开场提示／窗口切换、输入与确认、变化强调、收束落版；音乐节奏基线 |
| 验证 | 成片逐镜头真实性复核表；模拟数据说明；单一作业信息一致性检查 |

## 4. 待确认的制作决策

1. **最终 Logo 源文件**及“G + 一横一竖 → 标签”的准确几何路径。
2. **视觉风格参考片**：深色空间、字体、卡片透视和强调色，需要选定参考并编译为统一 visual DNA。
3. **真实 UI 与重设计 UI 的比例**：哪些操作保留产品截图，哪些采用保留交互语义的重设计画面。
4. **声音主导方式**：纯音乐 + 屏幕短句，还是英文旁白 + 音乐；这会直接影响每镜头时长。
5. **正式录屏环境**：选定可重复触发保存、监测与版本差异的模拟校园页面；避免把未验收的真实学校会话当作演示前提。
6. **Gleaner 品牌文字**：录屏前移除插件和客户端界面中残留的历史产品名称，保证最终画面统一。

**当前结论**：按 25 个镜头准备关键帧和界面素材；Problem 结尾使用大字反问字幕，无需额外的信息更新场景。旁白和精确剪辑时间线仍可迭代。
