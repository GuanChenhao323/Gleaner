# Gleaner｜产品营销视频细化分镜与素材约束

> **版本**：v0.1 · 2026-11-19  
> **状态**：预制作方案（Pre-production），用于镜头设计和素材规划；尚未批准为最终拍摄脚本  
> **上级文档**：[产品营销视频叙事大纲](./video-narrative-outline.md)  
> **目标**：将 7 个叙事板块细化为可执行的镜头、画面信息、动效与转场，并明确可虚构素材的边界。  
> **建议规格**：16:9 横版；约 85 秒；7 个板块、21 个实际镜头。时间为节奏参考，可根据音乐与实拍素材调整。

## 0. 创作定位与统一视觉规则

### 0.1 一句话故事

**重要信息分散在不同的数字窗口里；Gleaner 让用户将值得关注的信息采集、整理，并在已保存来源发生变化时持续跟进。**

故事的开端具有普遍性，完整操作演示采用大学生的课程作业作为具体案例（**especially for students**）。

**连续的视觉动词**：Scattered → Focused → Captured → Organized → Updated → Unified。

### 0.2 Window-first：以应用窗口为画面主体

- **窗口是主角**：网页窗口、浏览器插件面板、工作台、Inbox 和事项详情窗口可以脱离操作系统桌面独立存在。
- **不要求展示整台 Mac**：Mac 风格设备只是一种可选开场参考；菜单栏、Dock、桌面壁纸不是固定构图要素。
- **点击即聚焦**：用户点开插件后，镜头立刻推进到插件面板；放大面板可以占据画面主要面积，确保文字可读。
- **窗口外是可设计空间**：使用深色纯背景、渐变、抽象空间、悬浮信息层或 2.5D 透视。外部背景服务于窗口主体。
- **一个镜头只传达一个主要信息**：少量可读字段配合有目的的动效，避免同时显示过多文字或效果。
- **避免镜头漂移**：尽量一镜一个主要摄影机动作（推进、横移、拉远或固定），同时明确起始帧和结束帧。

### 0.3 统一的视觉 DNA（待根据正式 Logo 微调）

| 视觉维度 | 暂定规则 | 作用 |
| --- | --- | --- |
| 空间 | 深色中性背景、悬浮应用窗口、清晰的前后层次 | 托起产品界面，形成高级感 |
| 配色 | 中性色为底；从正式 Gleaner Logo／界面抽取一种主强调色；变化提示另用有限状态色 | 保持品牌一致、避免彩色信息噪声 |
| 形状 | 统一圆角、阴影、窗口厚度；信息卡片采用同一套圆角几何 | 让跨镜头元素像同一个产品世界 |
| 运动 | 开头快速、略失序；Gleaner 出场后逐渐顺滑；变更时短促强调；结尾收束 | 用运动节奏呈现“混乱 → 秩序” |
| 镜头 | 以正视和轻微 2.5D 透视为主，操作细节始终保持可读 | 避免 3D 旋转牺牲 UI 识别 |
| 声音 | 开头叠加消息提示／窗口切换声，采集处出现确认感，变化对比处高潮，Logo 落点收尾 | 声音强化信息因果与节奏 |

> **使用原则**：先锁定每个镜头的起始／结束画面，再决定运动和音效。参考 `content-engine` 的 visual DNA、start-frame-first 与节奏设计思路；具体生成模型和剪辑工具尚不决定。

## 1. 素材约束模型：允许 fake 什么

### 1.1 三类素材

| 类型 | 名称 | 允许的操作 | 边界与验证 |
| --- | --- | --- | --- |
| **A** | 真实产品素材（Real Product） | 录制当前可运行的浏览器插件、Gleaner 工作台、Inbox、状态管理和变更详情；可裁切、放大、调色、加遮罩 | 关键按钮、交互因果和结果必须与实际产品功能一致 |
| **B** | 合成／重设计的演示素材（Synthetic Demo） | 虚构课程名、作业正文、日期、校园网页、邮件和聊天内容；美化页面排版；用模拟网页注入可重复的内容变化 | 只能合成**数据、场景与视觉样式**，不可暗示已接入所有 App／真实校园平台或拥有尚未完成的功能 |
| **C** | 纯 Motion Design（Visual FX） | 悬浮窗口、卡片飞行、信息拆解、字段重组、光线、粒子、时间变化强调、Logo 聚合 | 动效是帮助理解的视觉隐喻，不代表产品实际有“飞行卡片／实时推送／全自动跨 App 抓取”等功能 |

**必要时允许 A+B+C 合成同一镜头**：例如用真实插件录屏作 UI 核心，替换为合成作业内容，再制作关键词命中或卡片飞行特效。每个镜头均标记主要素材类别。

### 1.2 不得越过的真实性边界

1. **功能不可凭空增加**：开头展示多个 App 仅代表信息分散，不表示 Gleaner 已接入或实时读取它们。
2. **保留用户主动操作**：Capture 的关键词搜索、预览、选取和保存属于用户操作。演示卡片可以虚构，步骤因果不能跳过。
3. **监测必须有条件**：仅对已保存、可监测且启用监测的来源进行检查；经过下一次**成功检查**后才出现变化提示。不得将其剪成“原网页刚改、任意地点立即推送”的产品承诺。
4. **差异必须可追溯**：同一作业的标题、来源、旧截止时间与新截止时间保持一致；Before / After 应清楚展示改变了什么。
5. **不得冒充生产环境**：模拟网页、虚构账号及合成数据统一作为演示素材。成片可在片尾或说明中标注 `Demonstration with simulated data`，不把模拟内容包装为真实校园用户证据。
6. **Logo 不可随意改形**：最后一横一竖与“标签形”的几何关系需以最终确认的 Logo 文件为准；动画可以夸张，落版必须准确。

### 1.3 单一贯穿用例（固定道具）

为避免镜头间信息失配，先冻结一组**完全虚构的演示数据**：

| 字段 | 演示值 |
| --- | --- |
| 来源类别 | Moodle 风格的模拟课程作业页 |
| 课程 | Computer Networks |
| 作业标题 | Socket Lab 03 — TCP Echo Server |
| 简述 | Implement and submit a TCP echo server |
| 初始截止 | **Fri, Dec 11, 2026 · 23:59** |
| 修改后截止 | **Thu, Dec 10, 2026 · 23:59** |
| Gleaner 类型 | 待办（Todo） |
| 保存状态 | 未完成（To do） |
| 变化事件 | 截止日期提前一天；同一个来源、同一条作业 |
| 来源地址 | 使用虚构测试域名（如 `moodle.example.test`），不展示真实学生隐私、Cookie 或有效凭证 |

除非后续替换整个测试素材包，**所有镜头复用这一组名称、字段和日期**。视觉元素可重排，数据不能前后矛盾。

## Scene 01

**Introducing · 开场（00:00–00:04，2 镜头）**  
**板块目标**：让观众在几秒内认出“不同的数字信息窗口”；不急于解释 Gleaner。

### Shot 01A｜第一扇窗口出现（00:00–00:02）

- **主窗口 / 画面内容**：深色空间中央出现一个干净的网页窗口，局部显示作业或消息标题；窗口边框和阴影统一。
- **起始帧**：几乎全空的暗色背景，中央只有很小的光点或线条。
- **过程**：轻微推近，窗口从薄线扩展为完整矩形；标题逐步变得清楚。
- **结束帧 / 转场**：第一张窗口停稳，右侧留白中出现第二张窗口的边缘，为下一镜头铺垫。
- **素材**：B（合成界面）+ C（展开与空间动效）；**一句话信息**：Important information appears everywhere。
- **声音**：一个轻微提示音或清晰的开场落点。

### Shot 01B｜信息开始增殖（00:02–00:04）

- **主窗口 / 画面内容**：新的消息、通知和日历窗口沿不同深度弹入，形成最初的层叠。
- **起始帧**：Shot 01A 的窗口保持位置。
- **过程**：两到三个窗口快速加入；窗口标识可出现 Email、Calendar、Browser 等通用类别。
- **结束帧 / 转场**：最后弹入的窗口运动方向延伸至 Scene 02，开始更密集的叠加。
- **素材**：B+C；**屏幕候选文案**：`Information is everywhere.`。
- **声音**：提示音由单点扩展为略密集的节奏。

## Scene 02

**Problem · 信息分散（00:04–00:16，3 镜头）**  
**板块目标**：通过窗口的空间关系，让观众无需人物出镜就理解“信息散落在多个 App 和网页”。

### Shot 02A｜多来源同时出现（00:04–00:08）

- **主窗口 / 画面内容**：5–6 个具有不同视觉识别的窗口悬浮排开：课程网页、学院公告、Email、Calendar、Notes、聊天消息。
- **起始帧**：沿用上一镜头的窗口群。
- **过程**：快速横移镜头，依次扫过各窗口里少量可读关键词：`Assignment`、`Announcement`、`Deadline`、`Event`。
- **结束帧 / 转场**：镜头在 Moodle 风格课程窗口稍作停顿，但不立刻进入操作。
- **素材**：B（合成内容）+ C（分层/镜头移动）；**注意**：这些是问题来源示意，不能出现暗示已成功连接 Gleaner 的图标或状态。

### Shot 02B｜同一件事散落多处（00:08–00:12）

- **主窗口 / 画面内容**：一个窗口里有作业标题，另一窗口里有日历提醒，另一个窗口里有关于截止时间的消息片段。
- **起始帧**：三个窗口在画面不同方位，彼此缺少关联。
- **过程**：高亮标题、日期和要求三个信息片段；用短线或光标尝试“寻找联系”，但它们仍分散在不同窗口。
- **结束帧 / 转场**：重要的 `Due Friday` 被另一张窗口遮住。
- **素材**：B+C；**核心信息**：信息存在，却难以集中追踪。

### Shot 02C｜窗口挤压，问题定格（00:12–00:16）

- **主窗口 / 画面内容**：窗口继续叠加，原本重要的日期被盖住，画面出现轻微失序和空间拥堵。
- **起始帧**：Shot 02B 的三个信息点已经难以同时阅读。
- **过程**：短暂加速、局部窗口快速前后切换；最终瞬间静止，减少环境声音。
- **结束帧 / 转场**：唯一与课程作业有关的卡片保持高亮，其余窗口变暗。为 Gleaner 的“聚焦”登场做准备。
- **素材**：B+C；**屏幕候选文案**：`Too many places. Too much to track.`。

## Scene 03

**Meet Gleaner · 产品登场（00:16–00:21，2 镜头）**  
**板块目标**：将“窗口混乱”迅速过渡为“一个可操作的产品入口”。

### Shot 03A｜锁定一条重要信息（00:16–00:18）

- **主窗口 / 画面内容**：从混乱窗口群中突出 Moodle 风格作业窗口，其他窗口沿景深退后或淡出。
- **起始帧**：Scene 02 最后一帧静止。
- **过程**：镜头快速推进高亮卡片，卡片内的 `Socket Lab 03` 成为焦点。
- **结束帧 / 转场**：视觉中心落在浏览器窗口的插件入口附近。
- **素材**：B+C；**核心信息**：用户已经找到需要保存的内容。

### Shot 03B｜Gleaner 弹出并占据主画面（00:18–00:21）

- **主窗口 / 画面内容**：点击 Gleaner 扩展图标，出现插件面板；同时短暂显示产品名称 `Gleaner`。
- **起始帧**：浏览器窗口可见、插件尚未打开。
- **过程**：插件面板弹出，镜头立即通过裁切／推近让**插件窗口填满主要画面**；浏览器壳体迅速退出镜头。
- **结束帧 / 转场**：插件输入框处于视觉中心，直接进入 Scene 04 的关键词输入。
- **素材**：A（产品插件流程）+ B（合成页面）+ C（空间变焦）；**关键原则**：只展示必要的浏览器上下文，不保留完整 Mac 桌面。

## Scene 04

**Capture · 网页信息采集（00:21–00:39，4 镜头）**  
**板块目标**：清晰证明 Gleaner 的输入、提取、预览、选择、保存流程。此段可以更快切镜，操作对象始终可读。

### Shot 04A｜建立作业来源（00:21–00:25）

- **主窗口 / 画面内容**：模拟 Moodle 课程作业页，突出标题 `Socket Lab 03 — TCP Echo Server`、简述与初始截止 `Fri, Dec 11`。
- **起始帧**：浏览器页面在画面中清晰呈现，焦点从插件入口落回原始作业内容。
- **过程**：短促高亮标题和截止时间，说明本次要保存的对象。
- **结束帧 / 转场**：插件窗口沿原入口快速覆盖网页的一部分，形成下一镜头的主画面。
- **素材**：B（高质量模拟网页）+ C（高亮）；**防误解**：不能使用真实学校账号资料或暗示真实高校内容已被验证。

### Shot 04B｜输入关键词（00:25–00:29）

- **主窗口 / 画面内容**：Gleaner 插件**特写**，可见 `你想提取什么？` 的输入框和提取按钮。
- **起始帧**：面板占据画面主要面积，光标在输入框。
- **过程**：键入 `Socket Lab`，触发“提取”；用细微的输入音效和明确的按钮反馈强调动作。
- **结束帧 / 转场**：面板下方留出展示结果的位置，镜头不再频繁移动。
- **素材**：A（产品输入行为）+ B（合成数据）+ C（镜头放大）；**核心信息**：用户主动指定关心的内容。

### Shot 04C｜匹配、预览、选择（00:29–00:34）

- **主窗口 / 画面内容**：插件的结果列表展示 `Socket Lab 03`，可看到标题、相关内容、来源和已识别的截止信息。
- **起始帧**：结果区为空或加载中。
- **过程**：匹配卡片按层级依次展开，焦点停在目标作业；使用产品实际支持的预览／选择动作。
- **结束帧 / 转场**：目标卡片被确认选中，保存按钮成为唯一高对比操作点。
- **素材**：A+B+C；**不得制造**当前尚未支持的“无限网页自动全量抓取”或多 App 读取能力。

### Shot 04D｜保存成功，卡片飞出（00:34–00:39）

- **主窗口 / 画面内容**：点击保存；插件显示成功回执；目标内容凝结为一张具有一致标题和截止日期的卡片。
- **起始帧**：目标记录已选中，保存按钮待点击。
- **过程**：一次点击、一次成功反馈；镜头跟随卡片从插件面板“抽离”，向画面另一侧飞行。
- **结束帧 / 转场**：卡片飞入一个由网格和空白栏位构成的工作台空间，成为 Scene 05 的第一张素材。
- **素材**：A（保存行为与反馈）+ B（演示数据）+ C（**飞行完全为视觉隐喻**）；**核心信息**：从网页进入 Gleaner。

## Scene 05

**Organize · 整理与归类（00:39–00:56，3 镜头）**  
**板块目标**：让观众看到“原始网页内容”如何转化成“能持续管理的个人事项”。

### Shot 05A｜信息拆解为字段（00:39–00:44）

- **主窗口 / 画面内容**：上一镜头飞来的作业卡片悬停，分解成 `Title`、`Due date`、`Source`、`Status` 四个信息块。
- **起始帧**：完整卡片居中。
- **过程**：卡片按字段轻柔展开，字段标签逐个出现；不需要展示解析算法或 LLM。
- **结束帧 / 转场**：四个信息块沿网格位置对齐，准备组成任务卡片。
- **素材**：B+C；**含义**：结构化信息的抽象可视化，不表示真实界面存在“拆解动画”。

### Shot 05B｜归入分类（00:44–00:50）

- **主窗口 / 画面内容**：Gleaner 工作台窗口出现，`Socket Lab 03` 被组合成含截止时间、来源与待办状态的卡片，落入待办视图。
- **起始帧**：工作台网格与分类入口先显示，卡片尚未落位。
- **过程**：任务卡片定位至 `Todo`；其他演示卡片分别进入 `Events`、`Notices`，形成分类秩序。
- **结束帧 / 转场**：所有卡片稳定排列，镜头逐渐拉远。
- **素材**：A（实际工作台层级）+ B（合成数据／允许重排）+ C（自动归位视觉效果）；**防误解**：不要把拟议模板树表现为已在所有网站全面支持。

### Shot 05C｜管理状态，完成闭环（00:50–00:56）

- **主窗口 / 画面内容**：完整的 Gleaner 工作台；重点可见“本周”截止事项、待办分类及新保存的作业。
- **起始帧**：整齐排列的任务卡片。

## 3. 镜头间连续性与验收检查

### 3.1 关键连续转场

| 衔接 | 具体转场关系 | 设计目的 |
| --- | --- | --- |
| 01 → 02 | 第一张窗口扩展为多窗口层叠 | 逐步建立分散感 |
| 02 → 03 | 混乱定格，仅保留一条作业高亮 | 注意力从问题收敛 |
| 03 → 04 | 点击扩展图标，镜头迅速进入插件窗口 | 让 Gleaner 成为绝对主角 |
| 04 → 05 | 保存回执后的作业卡片飞入工作台、拆分并重组 | 强化 Capture → Organize 的连续因果 |
| 05 → 06 | 从工作台里的同一个截止日期匹配切回原始网页 | 让“来源变化”有明确参照 |
| 06 → 07 | Before / After 差异卡片化为线条，吸引其他信息元素聚集 | 差异化高潮自然导向品牌收束 |

### 3.2 每镜头的质量门槛

- **可读性**：关键信息（标题、关键词、截止时间、变化前后对比）停留足够久，观众无需暂停即可理解。
- **单一意图**：每个镜头能用一句话说清自己要证明的东西；无意义视觉炫技删掉。
- **视觉一致性**：同一信息卡片的标题、日期、色彩角色、圆角和信息层级保持一致。
- **动作闭环**：镜头必须描述开始、动作、结束，避免“卡片一直漂浮”却没有明确落点。
- **功能可信**：A 类真实操作需要复录、核对保存结果与监测结果；B 类仅改内容或造演示情境；C 类不伪装成原生功能。
- **品牌一致性**：最后 G → 标签的绘制路径必须先经过 Logo 几何确认。
- **声音节奏**：窗口失序与信息出现相对应，采集成功有确认落点，差异对比是全片最强声音与画面强调点。

### 3.3 最小素材清单（后续制作阶段使用）

| 素材组 | 最小需要 |
| --- | --- |
| A · 产品录屏 | 关键词提取→预览→保存成功；工作台分类／详情；Inbox 变化状态；来源差异对比 |
| B · 演示数据 | 一套模拟 Moodle 作业页的修改前／修改后版本；多来源问题段的 Email／Calendar／公告／笔记窗口；一致的文案与日期 |
| C · 动效资源 | 一套悬浮窗口模板；卡片分解／归类动画；变化高亮和 Before/After；Logo 矢量路径与逐笔动画 |
| 声音 | 开场提示／窗口切换、输入与确认、变化强调、收束落版；音乐节奏基线 |
| 验证 | 成片逐镜头真实性复核表；模拟数据说明；单一作业信息一致性检查 |

## 4. 待确认的制作决策

1. **最终 Logo 源文件**及“G + 一横一竖 → 标签”的准确几何路径。
2. **视觉风格参考片**：深色空间、字体、卡片透视和强调色，需要选定参考并编译为统一 visual DNA。
3. **真实 UI 与重设计 UI 的比例**：哪些操作保留产品截图，哪些采用保留交互语义的重设计画面。
4. **声音主导方式**：纯音乐 + 屏幕短句，还是英文旁白 + 音乐；这会直接影响每镜头时长。
5. **正式录屏环境**：选定可重复触发保存、监测与版本差异的模拟校园页面；避免把未验收的真实学校会话当作演示前提。
6. **Gleaner 品牌文字**：录屏前移除插件和客户端界面中残留的历史产品名称，保证最终画面统一。

**当前结论**：先按这 21 个镜头准备关键帧与界面素材；确认视觉系统和真实功能镜头后，再定拍摄版 Storyboard、旁白和精确剪辑时间线。
