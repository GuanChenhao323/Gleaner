# Gleaner｜产品营销视频叙事大纲

> **版本**：v0.1（2026-11-19）  
> **状态**：叙事框架初稿，供讨论与迭代  
> **目标产物**：确定视频包含哪些内容、划分多少个叙事板块，以及每个板块主要讲什么。暂不展开逐镜头脚本、配音、精确时长和制作参数。

## 1. 视频定位

### 1.1 目标

制作一支具有完整故事感与视觉冲击力的 **Gleaner 产品营销 Demo 视频**，让观众理解产品解决的问题、体验核心能力，并对品牌留下记忆。

视频主要负责传达产品价值与使用体验。网络协议、服务器架构等技术细节由课程展示 PPT 的其他章节说明。

### 1.2 四个产品营销要素

| 要素 | 当前叙事共识 |
| --- | --- |
| **Product Overview** | Gleaner 帮助用户从网页获取值得关注的信息，将其整理为可管理的事项，并跟踪已保存来源的变化。长期产品想象空间不局限于校园。 |
| **Target Audience** | 面向需要管理分散数字信息的人群；本支视频采用大学生日常学习作为主要示例，即 **especially for students**。 |
| **Problems** | 重要信息散布在不同 App、网页与信息入口中。用户需要在多个窗口间切换、重新寻找并手工整理；原始信息更新后还可能需要反复核对。 |
| **Differentiation** | **Capture → Organize → Stay Updated**：从信息获取、结构化管理到来源变化追踪，形成连续的使用体验。 |

### 1.3 核心叙事原则

- **无需真人出场**：以一台 Mac 风格电脑为视觉舞台，通过桌面、应用窗口、网页、信息卡片及界面动效讲述故事。
- **先展示普遍问题，再落到学生场景**：开头可以出现多种 App 和网页；后续选取一条 Moodle 作业信息贯穿采集、管理和变化监测。
- **连贯故事优先**：核心功能围绕同一条信息的旅程展开，避免三段相互独立的功能介绍。
- **产品感知优先**：强调直观操作、流畅转场与信息从混乱到有序的视觉变化；不在视频中讲技术实现。

## 2. 视频结构：7 个叙事板块

> 下列“分镜”指视频的大叙事段落。后续制作时，每个板块可进一步拆分为若干镜头；目前不固定镜头数和时长。

### 01｜Introducing：引出主题

**主要内容**  
通过简短、有节奏的视觉开场建立“数字信息无处不在”的氛围，为接下来的问题场景做铺垫。

**画面方向**  
简洁背景上一台电脑逐渐出现，少量应用图标、页面卡片或通知元素浮现。画面保持克制，先制造期待，暂不讲具体产品功能。

**希望传达**  
重要信息存在于日常使用的各种数字工具之中。

### 02｜Problem：信息分散

**主要内容**  
用一个直观场景说明：同一个人每天需要在多个 App、网页和记录工具之间寻找、核对、整理重要信息。

**画面方向**  
镜头聚焦电脑屏幕。多个应用与网页窗口依次出现并叠加，例如课程页面、学院公告网页、邮件、日历、聊天工具和笔记。不同信息散落在各个窗口中，窗口切换越来越频繁，视觉上形成碎片化与拥挤感。

**希望传达**  
问题的核心是 **information is scattered**。不需要真人、人物表演或复杂剧情；观众仅凭窗口与信息的分布就能理解痛点。

### 03｜Meet Gleaner：产品登场

**主要内容**  
Gleaner 作为解决信息分散问题的统一入口登场，建立品牌和产品能力之间的联系。

**画面方向**  
杂乱窗口停止运动、让出视觉中心，Gleaner 的名称与产品界面出现。视觉语言从拥挤切换为清晰，为后续操作演示建立统一风格。

**希望传达**  
Gleaner 可以将有价值的网页信息带入一个更易管理的工作流。

### 04｜Capture：从网页采集信息

**主要内容**  
展示学生在浏览器中的真实操作：打开课程相关网页，点开 Gleaner 插件，输入关键词，查看匹配内容，确认并保存。

**画面方向**  
以 Moodle 作业页面为具体示例。重点呈现 **输入关键词 → 匹配预览 → 选择／保存 → 成功反馈**。用信息卡片向 Gleaner 工作台流动的转场，连接下一个板块。

**希望传达**  
用户可以轻量地保存自己关心的信息，减少手工复制和重新录入。

### 05｜Organize：整理与归类

**主要内容**  
展示被保存的信息如何进入 Gleaner，并成为更清晰、可管理的事项。

**画面方向**  
刚才的作业内容在工作台中转化为带标题、截止日期、来源和处理状态的待办卡片；同时展示工作台对待办、日程、通知等信息的分类呈现。通过卡片自动归位、排列和聚合的动效，体现从原始内容到结构化信息的变化。

**希望传达**  
**从信息到行动**：信息被保存后，可以持续查看、分类和管理。

### 06｜Stay Updated：追踪来源变化（叙事高潮）

**主要内容**  
同一份作业的原始网页发生修改，例如老师提前截止时间。Gleaner 在后续成功检查该已保存、已启用且支持监测的来源后，在 Inbox／事项详情中提示变化，并展示前后差异。

**画面方向**  
画面回到原作业页，截止日期发生变化；随后转入 Gleaner，突出一条来源更新提示。用户打开记录，清晰地看到 **Before / After** 对比，理解变化的内容。

**希望传达**  
保存信息之后，Gleaner 还帮助用户关注来源的后续变化，减少重复回访和漏看更新的成本。这是视频重点突出的差异化能力。

### 07｜Brand Ending：Logo 动画收束

**主要内容**  
将前面分散出现的信息元素收束成统一的 Gleaner 品牌符号，形成视觉闭环。

**画面方向**  
应用窗口、信息卡片、线条与碎片逐渐向画面中央聚合，先形成一个 **“G”**；随后在这一形态上动态补出 **一横与一竖**，最终成为类似标签轮廓的 Gleaner 商标。最后展示完整 Logo 与产品名称。实际路径以正式 Logo 图形为准。

**希望传达**  
从分散到聚合、从杂乱到有序，让品牌图形承接整个视频的主题。

## 3. 内容组织与重点

| 叙事阶段 | 包含板块 | 主要任务 |
| --- | --- | --- |
| **建立问题** | 01 Introducing、02 Problem | 用熟悉的数字场景建立共鸣，重点表达多 App／多网页的信息分散。 |
| **提出解决方案** | 03 Meet Gleaner、04 Capture、05 Organize | 介绍 Gleaner，展示网页采集与信息归类的连续体验。 |
| **突出差异化** | 06 Stay Updated | 用同一条作业来源的更新，集中呈现监测与变化对比的价值。 |
| **品牌记忆** | 07 Brand Ending | 用“信息聚合为 G、再形成标签形 Logo”的动效完成收束。 |

**视觉主线**：分散的信息 → 被选中 → 成为有序记录 → 来源变化被发现 → 信息元素汇聚成 Gleaner。

## 4. 演示边界与后续细化

### 4.1 本版需要遵守的表达边界

- 开场出现多个 App、网页，是为了说明用户痛点，**不代表当前 Gleaner 已支持直接采集所有 App 或任意网页**。
- Capture 段使用当前已实现并可演示的浏览器插件流程。
- 变化监测只展示已保存、支持并启用监测的来源；采用模拟校园页面或已验证的演示环境。**不暗示实时、全天候、无条件监测**。
- 视频不展示后台架构、网络协议或性能测试；这些留给 PPT 的技术章节。

### 4.2 下一阶段再确定的内容

1. 各叙事板块的时长与实际镜头数量。
2. 每个镜头的具体画面、转场和动效设计。
3. 英文旁白、画面短句及结尾品牌口号。
4. 整体视觉风格与最终 Logo 的精确绘制路径。
5. 用于录屏的固定演示数据、页面与工作台状态。
